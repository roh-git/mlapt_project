# 전체 테이블 추가 삭제 제언 및 최적화 방안

전체 테이블 간의 연결성(Join)과 기획안의 분석 타겟(공용관리비 상승 요인, 장기수선비 예측)을 아우르는 관점에서 보았을 때, 모델의 성능을 높이고 불필요한 노이즈를 줄이기 위해 추가로 덜어내면 좋은 칼럼들을 정리했습니다.

## 1. 테이블 간 100% 중복되는 칼럼 (조인 후 중복)
단지코드를 기준으로 테이블들을 병합(Merge)할 때 겹치게 되므로, Sub 테이블에서는 지우는 것이 좋습니다.
* **[면적정보]의 `동수`, `세대수`**: 이미 메인 테이블인 [기본정보]에 완벽히 똑같이 존재합니다. 
* **[기본정보]의 `동리`**: [위치정보]에 위도/경도가 있고, [기본정보]에 시군구와 도로명주소가 있습니다. 분석 시 동(Dong) 단위로 Grouping 할 게 아니라면, 주소 텍스트 파편화를 막기 위해 삭제하는 것이 깔끔합니다.

## 2. 비용 타겟과 완전 무관한 고정값 (개별사용료 성격)
* **[관리비]의 `TV수신료`**: 세대당 일정액 부과되는 법정 고정 요금입니다. 단지 규모의 경제나 관리 복잡성과 전혀 무관하므로 분석에 아무런 의미가 없습니다.
* **[시설정보]의 `홈네트워크`**: 세대 내부 인프라에 가까워 공용 시설 유지비나 경비/청소비 인상과 통계적 인과관계가 매우 떨어집니다.

## 3. 노이즈를 유발하는 미세 비용 및 다중공선성 요인
* **[관리비]의 `피복비`, `교육훈련비`, `선관위운영비`**: 공용관리비이긴 하나 금액 비중이 너무 미미하고 0원인 달이 많아(Sparse Data), 추세를 분석하는 모델에 들어가면 노이즈(Noise)만 유발합니다. 
* **[관리비]의 `위탁관리수수료`**: 위탁관리인 경우에만 발생하는데, 이 금액은 세대수나 면적에 칼같이 비례하는 경우가 많습니다. 모델에 넣으면 '면적/세대수'와 다중공선성(Multicollinearity) 문제를 일으키므로 제외하는 것이 회귀분석에 유리합니다.

## 4. 대체 지표가 이미 존재하는 범주형 데이터
* **[운영정보]의 `세부 관리방식(일반/경비/청소/소독)`**: 비용(관리비)을 결정하는 핵심은 관리 방식(위탁/직영)이 아니라, 투입된 '인원수(Numeric)'입니다. 각 항목별 '인원수' 칼럼은 살려두되, 세부 관리 방식 칼럼들은 지워도 좋습니다. (전체 관리 방식은 [기본정보]에 이미 존재)
* **[장기수선]의 `장충금 적립률`**: 관리소마다 계산 방식에 오류가 많아 신뢰도가 낮습니다. 분석가 입장에서는 이미 `월부과액`과 `총적립금액` 데이터가 있으므로, 직접 나누어서 파생 변수로 쓰는 것이 훨씬 정확합니다.
